04. Linked Lists

Q1
On a 64-bit operating system, how much memory is consumed by a pointer variable?
On 64-bit architectures, memory addresses are 64-bit integers, meaning all pointer variables consume exactly 8 bytes of storage.
Q2
When inserting a new node at the front of a singly linked list (push_front), what pointer assignment must occur first to prevent losing list access?
You must first point the new node's next to the current head: new_node->next = head; before updating the head pointer.
Q3
What is the worst-case time complexity of inserting an element at position k (where 0 < k < N) in a singly linked list of size N?
In a singly linked list, accessing position $k$ requires traversing the list from head node. This traversal takes linear $\mathcal{O}(N)$ time.
Q4
Which algorithm is used to detect cycles in a linked list using two pointers moving at different speeds?
Floyd's Cycle-Finding Algorithm uses a slow pointer moving 1 step and a fast pointer moving 2 steps.
Q5
How many link pointers are stored in each node of a Doubly Linked List?
Each node in a doubly linked list stores two pointers: next and prev.
Q6
What is the time complexity to delete a node at the tail of a Singly Linked List of size N, if we only maintain a head and tail pointer?
Although we have a tail pointer, deleting the tail requires updating the second-to-last node's next pointer to nullptr, which takes $O(N)$ traversal time.
Q7
What is a Circular Linked List?
A circular linked list forms a closed ring, so the last (tail) node points directly back to the first (head) node.
Q8
To find the middle element of a linked list in a single pass, we should use:
Using the two-pointer technique: when the fast pointer reaches the tail, the slow pointer will be exactly at the middle node.
Q9
What is the auxiliary space complexity of reversing a singly linked list of size N iteratively?
Reversing iteratively only requires updating pointers in-place using a few temporary variables, yielding constant $O(1)$ space.
Q10
What is a Skip List and what is its average search complexity?
A Skip List is a probabilistic data structure that layers multiple linked lists, allowing search, insert, and delete operations to run in $O(\log N)$ average time.
Q11
What is the main benefit of a Doubly Linked List over a Singly Linked List?
Because doubly linked list nodes store pointers to both next and prev nodes, we can detach a node in-place in $O(1)$ without traversing to find its predecessor.
Q12
In a circular linked list, what does the tail node's next pointer refer to?
A circular list forms a closed ring, so the last (tail) node points directly back to the first (head) node.
Q13
What occurs during a 'dereferencing nullptr' error in a linked list operation?
Null pointers do not refer to valid memory addresses. Accessing `ptr->next` or `ptr->val` when `ptr` is nullptr triggers a runtime segmentation fault.
Q14
What is the time complexity to find the length of a singly linked list if no length variable is cached?
Without a cached counter, we must traverse the list from head to tail node, visiting all $N$ nodes in $O(N)$ time.
Q15
What is the key advantage of using a Sentinel (Dummy) Node in Linked Lists?
With a dummy node, head is never nullptr, eliminating the need to write special code branches to handle empty lists or head changes.
Q16
What is the output of the following linked list wiring logic?
struct Node { int val; Node* next; };
Node* head = new Node{1, nullptr};
Node* temp = new Node{2, nullptr};
temp->next = head;
head = temp;
std::cout << head->val << " " << head->next->val;
temp is initialized with val 2 and its next is set to head (which is 1). Then head is set to temp. Thus head->val is 2 and head->next->val is 1.
Q17
Where does pointer curr point after executing this loop on the list 1 -> 2 -> 3 -> 4 -> nullptr?
Node* curr = head;
while(curr != nullptr && curr->next != nullptr) {
    curr = curr->next->next;
}
Initially curr is at 1. First iteration: moves to curr->next->next which is 3. Second iteration: curr->next is 4, next->next is nullptr, so curr becomes nullptr. Loop terminates.
Q18
Trace inserting a new node with value 99 between nodes holding 10 and 20 in the list 10 -> 20 -> 30. Using a pointer prev pointing at the node holding 10, which statement order correctly performs the insertion?
You must first save the old next pointer (node holding 20) into newNode->next BEFORE overwriting prev->next, otherwise the link to the rest of the list (20 -> 30) is lost. Reversing the order (option B) would make newNode->next point to newNode itself, breaking the list.
Q19
Trace this singly linked list deletion. Given 5 -> 8 -> 12 -> nullptr with prev at the node holding 5, what is the list after executing Node* target = prev->next; prev->next = target->next; delete target;?
target points to the node holding 8. prev->next is rewired to skip over it, pointing directly to the node holding 12 (target->next), before target is deleted. Result: 5 -> 12 -> nullptr.
Q20
What is the output of this pointer-swapping reversal trace on list 1 -> 2 -> 3 -> nullptr?
Node* prev = nullptr;
Node* curr = head; // points to 1
while (curr != nullptr) {
    Node* next = curr->next;
    curr->next = prev;
    prev = curr;
    curr = next;
}
head = prev;
This is the standard iterative in-place reversal. Each node's next pointer is redirected to point backward (toward prev) before advancing. After the loop, prev holds the new head, and the list is fully reversed: 3 -> 2 -> 1 -> nullptr.
Q21
Using Floyd's Cycle Detection (tortoise/hare, slow moves 1 step, fast moves 2 steps) on the list 1 -> 2 -> 3 -> 4 -> 2 (node 4 points back to node 2, forming a cycle), do slow and fast ever meet?
Because a cycle exists, fast can never reach nullptr — it keeps looping. Since fast gains on slow by 1 step every iteration within a finite cycle, they are mathematically guaranteed to eventually land on the same node.
Q22
In the Doubly Linked List insertion diagram (inserting node N after node P, before node S), what is the correct 4-step pointer sequence?
The safe order sets N's own pointers first (N->next = P->next which is S; N->prev = P), THEN fixes the old neighbor's back-pointer (P->next->prev = N, which must happen while P->next still refers to S, i.e. before overwriting P->next), and only last rewires P->next = N. Doing 'P->next = N' too early would lose the reference needed to update S->prev.
Q23
Given a singly linked list of size N with no tail pointer, what is the time complexity of push_back (inserting a new node at the end)?
Without a tail pointer, the only way to find the last node is to traverse the entire list starting from head, giving O(N). This is why the Queue_list implementation explicitly maintains a tail pointer to achieve O(1) enqueue.
Q24
Trace this code using the slow/fast pointer technique to find the middle node of 1 -> 2 -> 3 -> 4 -> 5 -> nullptr:
Node* slow = head;
Node* fast = head;
while (fast != nullptr && fast->next != nullptr) {
    slow = slow->next;
    fast = fast->next->next;
}
// slow now points to the middle
fast moves 2 steps for every 1 step slow moves. Starting both at node 1: after iter1, slow=2, fast=3; iter2: slow=3, fast=5; iter3 check: fast->next is nullptr, loop stops (fast=5, fast->next=nullptr). slow lands on node 3, the middle of 5 elements.
Q25
What does this code print, tracing pointer reassignment carefully?
struct Node { int val; Node* next; };
Node a{1, nullptr}, b{2, nullptr}, c{3, nullptr};
a.next = &b;
b.next = &c;
Node* p = &a;
p = p->next;
p->val = 99;
std::cout << a.next->val;
p starts at &a, then p = p->next moves it to &b. p->val = 99 modifies node b's value directly (since p now points to the same memory as b) — b.val becomes 99. a.next still points to &b, so a.next->val prints 99.
Q26
For a Circular Singly Linked List where tail->next points back to head, what condition correctly detects that the list is empty?
Regardless of the circular wiring among existing nodes, an empty list still has no nodes at all, so head (and tail) remain nullptr, same as a standard empty linked list. The circularity only applies once nodes exist.
Q27
A sentinel (dummy) head node is used so that dummy->next is the real head. What is the main benefit when deleting the actual first node of the list?
Without a sentinel, deleting the head requires special-case code (updating the head pointer itself, which has no 'previous' node). With a dummy node before the real head, every deletion — including the first real node — follows the identical 'unlink the node after prev' pattern, eliminating edge cases.
Q28
What is the auxiliary space complexity of the recursive (not iterative) version of linked list reversal for a list of size N?
Each recursive call adds a new stack frame that isn't resolved until the base case is reached and calls start returning, so the call stack grows to depth N in the worst case — O(N) auxiliary space, unlike the O(1) iterative version.
Q29
Trace merging two sorted lists 1 -> 3 -> 5 and 2 -> 4 using a dummy node and a tail pointer. What are the first three values appended to the merged result?
Compare fronts: 1 vs 2 -> append 1, advance list1 to 3. Compare 3 vs 2 -> append 2, advance list2 to 4. Compare 3 vs 4 -> append 3, advance list1 to 5. First three appended values: 1, 2, 3.
Q30
In the 'Remove Nth Node From End' technique using two pointers separated by a gap of N+1 (via a dummy node), for list 1 -> 2 -> 3 -> 4 -> 5 and N=2 (remove the 2nd node from the end), which node is removed?
The 2nd node from the end of [1,2,3,4,5] is 4 (the end is 5, one before it is 4). The two-pointer technique advances a fast pointer N+1 steps ahead first, then moves both together until fast reaches nullptr — at that point slow lands exactly before the target node, allowing its removal in one pass.
