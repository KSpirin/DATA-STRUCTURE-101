03. Queue ADT

Q1
In a Queue ADT, elements are inserted at the ______ and removed from the ______.
Queues follow First-In, First-Out (FIFO). New elements are enqueued at the back/rear, and removed from the front.
Q2
Which two operations, together, define the core behavior of a queue?
A queue's identity comes from restricting insertion to one end and removal to the other: enqueue adds an element to the back, and dequeue removes the element from the front.
Q3
Which data structure operates on a Restricted-Access FIFO policy?
Queues strictly restrict insertions to the back (enqueue) and deletions to the front (dequeue), enforcing First-In, First-Out (FIFO) policy.
Q4
Which real-world scenario best models how a Queue (FIFO) behaves?
A queue serves elements in the exact order they arrived, just like a line of people waiting their turn. The plate stack and laundry pile are LIFO examples (stack-like), not FIFO.
Q5
In an array-based Circular Queue of size N, which expression correctly wraps the tail pointer index iback during enqueue?
Circular indices wrap around using modulo capacity arithmetic: (index + 1) % N.
Q6
Which condition represents a full Circular Queue when the front index has wrapped around and now sits immediately after rear?
A circular queue is considered full under two configurations: (1) FRONT == 0 and REAR == SIZE - 1, or (2) FRONT == REAR + 1 after wrapping.
Q7
In a circular queue, which condition typically signals that the queue is empty?
When front and rear point to the same position, and no separate count is tracked, the queue is empty — there is nothing between front and rear to dequeue.
Q8
Why does a linear (non-circular) array-based queue suffer from 'false overflow', and how does a circular queue solve it?
In a plain array queue, rear keeps climbing with every enqueue and is never pulled back by dequeue, even though the freed slots at the front sit unused. Eventually rear hits the end of the array and reports 'full' even though space remains at the front — this is false overflow. A circular queue fixes it by wrapping rear (and front) around to index 0 with modulo arithmetic, reusing the freed slots.
Q9
In a Circular Queue of size N, how is the current size calculated from the front and rear indices?
If the queue has wrapped, rear < front. The general formula for the number of elements currently stored is (rear - front + N) % N.
Q10
What is the front index in a Circular Queue after enqueuing 3 elements and dequeueing 2 elements, starting from empty at index 0?
Enqueuing 3 elements fills indices 0, 1, 2. Dequeueing 2 elements removes index 0 and index 1. The front pointer now rests at index 2.
Q11
What are the values of rear and front after enqueuing 3 elements and dequeueing 2 elements in a Circular Queue? (0-indexed, starting empty at index 0.)
Enqueuing 3 elements fills index 0, 1, and 2, so rear ends at 2. Dequeuing 2 elements removes index 0 and 1, so front moves to index 2. Both front and rear now rest at index 2.
Q12
A Circular Queue has capacity N=5 (using the 'leave one slot empty' strategy) and starts with front=0, rear=0. After enqueue(A), enqueue(B), enqueue(C), enqueue(D), what are the values of front and rear?
Each enqueue writes at rear then advances: rear = (rear+1) % 5. Starting rear=0: after A, rear=1; after B, rear=2; after C, rear=3; after D, rear=4. front never moves during enqueue, so it stays 0. Final: front=0, rear=4.
Q13
Continuing from the same circular queue (N=5, front=0, rear=4 after enqueuing A,B,C,D), perform dequeue(); dequeue();. What are the new values of front and rear?
Each dequeue reads at front then advances: front = (front+1) % 5. Starting front=0: after the first dequeue (removes A), front=1; after the second (removes B), front=2. rear is untouched by dequeue, staying at 4. Final: front=2, rear=4.
Q14
In the 'leave one slot empty' circular queue strategy with capacity N=5, the queue is currently full according to (rear+1)%N == front. If front=3, what is rear?
Full condition: (rear+1) % 5 == front == 3, so rear+1 is congruent to 3 mod 5, meaning rear = 2, since (2+1)%5 = 3.
Q15
A circular queue has capacity N=4 (leave-one-slot strategy) and starts with front=0, rear=0. After enqueue(P); enqueue(Q); enqueue(R);, what are the values of front and rear?
Each enqueue writes at rear then advances: rear = (rear+1) % 4. Starting rear=0: after P, rear=1; after Q, rear=2; after R, rear=3. front never moves during enqueue, staying 0. Final: front=0, rear=3 — and since (rear+1)%4 == front, the queue is now full.
Q16
Using the 'Simple Queue' (non-circular, slide model) with a starting empty state, after enqueuing 4 elements the queue reports full() == true. If we now call dequeue() four times to empty it, can we enqueue(E) afterward? Why?
In the simple, non-circular array queue, rear only ever increases and is never reset by dequeue. After 4 enqueues, rear equals size, so full() stays true forever, even after the queue becomes logically empty. This is the 'Rightward Drift' problem that circular queues solve.
Q17
What is the time complexity of enqueuing an element into a Circular Queue?
Circular Queue insertions run in constant O(1) time.
Q18
What is the time complexity of checking whether a Queue is empty?
Checking if a queue is empty is a constant-time check: either testing size == 0 or front == rear (or front == -1 in some conventions).
Q19
In a well-implemented circular array queue with front, rear, and a size counter, which of these operations run in O(1) time?
Because a circular queue tracks front, rear, and size directly, enqueuing, dequeuing, peeking at the front, and checking emptiness can all be done with simple index math and no scanning. All are O(1).
Q20
Read the following queue simulation. What is printed?
#include <iostream>
#include <queue>
int main() {
    std::queue<int> q;
    q.push(1); q.push(2); q.push(3);
    q.pop();
    q.push(4);
    while(!q.empty()) {
        std::cout << q.front() << " ";
        q.pop();
    }
    return 0;
}
The queue starts as [1, 2, 3]. Popping removes the front element (1), leaving [2, 3]. Pushing 4 yields [2, 3, 4]. Printing the front and popping repeatedly outputs '2 3 4 '.
Q21
What is the output of this std::queue trace?
#include <iostream>
#include <queue>
int main() {
    std::queue<int> q;
    q.push(1); q.push(2); q.push(3);
    q.pop();
    q.push(4);
    std::cout << q.front() << " " << q.back();

push 1,2,3 -> queue: [1,2,3] (front=1). pop() removes 1 -> [2,3]. push(4) -> [2,3,4]. front() = 2, back() = 4. Output: '2 4'.
Q22
What happens if you call pop() on an empty std::queue in C++?
Like std::stack, std::queue does not check whether it is empty before popping. Calling pop() or front() on an empty queue is undefined behavior — the caller must check empty() first.
Q23
What is the difference between front() and pop() in std::queue?
front() returns a reference to the element at the front but leaves it in the queue. pop() removes the front element but does not return its value — code typically calls front() first to read it, then pop() to remove it.
Q24
After the sequence enqueue(10); enqueue(20); enqueue(30); dequeue(); enqueue(40);, what does size() return?
enqueue adds three elements (size 3), dequeue removes one (size 2), then enqueue adds one more (size 3). The queue ends with 3 elements.
Q25
Which situation causes a Queue Underflow?
Queue Underflow happens when we try to remove or read data (dequeue or front) from a queue that has no elements.
Q26
A Queue is implemented using two stacks, inStack and outStack. Enqueue always pushes onto inStack. Dequeue pops from outStack, refilling it from inStack whenever outStack is empty (by popping everything off inStack and pushing it onto outStack). Starting from both stacks empty, we call enqueue(1); enqueue(2); dequeue();. What is the state of the two stacks right after dequeue() finishes?
enqueue(1) and enqueue(2) both go onto inStack: inStack=[1,2]. On dequeue(), since outStack is empty, everything moves from inStack to outStack, reversing the order: outStack=[2,1] (1 on top). Popping outStack removes 1, the correct FIFO answer since 1 was enqueued first. After that pop, inStack is empty and outStack holds [2].
Q27
What is a Double-Ended Queue (Deque)?
A Deque (Double-Ended Queue) allows elements to be enqueued or dequeued from either the front or the back.
Q28
How does a Priority Queue differ from a standard FIFO Queue?
In a Priority Queue, elements are enqueued normally but dequeued based on priority, not on the order they arrived.
Q29
Which statement correctly distinguishes a Queue, a Deque, and a Priority Queue?
A plain Queue is strict FIFO. A Deque relaxes that by allowing insertion and removal at both the front and back. A Priority Queue relaxes it differently: elements come out based on priority value, regardless of when they arrived.
Q30
In a plain FIFO queue with no extra structure, what is the time complexity of finding the element with the highest priority among N elements?
A plain queue only lets us access the front element directly. To find the highest-priority element, we would need to scan every element, which takes O(N) time — this is exactly the gap a Priority Queue is designed to close.
