02. Stack ADT

Q1
Which of the following describes how a Stack works?
A stack follows Last-In, First-Out (LIFO) order. We can only insert and remove elements at one end, called the top.
Q2
Which two operations, together, define the core behavior of a stack?
A stack's identity comes from restricting insertion and removal to a single end: push adds an element to the top, and pop removes the element from the top.
Q3
Which of the following is NOT a typical application of a stack?
Breadth-first search uses a Queue, not a Stack, since it explores nodes level by level in the order they were discovered. The other options are all classic stack applications.
Q4
A stack uses a fixed-size array with capacity N. The variable top starts at 0. Each push stores data at index top, then increments top. Which condition means the stack is full?
Since top starts at 0 and increases by 1 after every push, top always equals the current number of elements. The stack becomes full when top reaches N.
Q5
What happens when a program tries to push a new element onto an array-based stack that is already full?
Pushing onto a stack that has no more room causes a Stack Overflow.
Q6
Which situation causes a Stack Underflow?
Stack Underflow happens when we try to remove or read data (pop or top) from a stack that has no elements.
Q7
A different stack implementation uses an array of capacity C, where the variable top starts at -1 to mean the stack is empty. Pushing increments top first, then stores data at Array[top]. Which pair of conditions correctly signals overflow and underflow?
With top starting at -1, the last valid array index is C - 1. If top already equals C - 1, there is no room for another push, so that is overflow. top == -1 means no elements are stored, which is exactly the underflow condition.
Q8
A stack is stored in an array where Array[0] holds the capacity, and the data is stored from index 1 to top. The stack starts empty (top = 0). Trace these calls in order: push(5); push(8); pop(); push(3);. What are the final values of top and Array[top]?
push(5): top = 1, Array[1] = 5. push(8): top = 2, Array[2] = 8. pop(): removes Array[2] = 8, top becomes 1. push(3): top = 2, Array[2] = 3. Final state: top = 2, Array[top] = 3.
Q9
A stack currently holds [X, Y, Z] with Z on top. We call push(W), then pop(), then pop(). What is the top element now?
Start: [X, Y, Z]. push(W): [X, Y, Z, W]. pop(): removes W, leaving [X, Y, Z]. pop(): removes Z, leaving [X, Y]. The top element is now Y.
Q10
Trace these operations on an initially empty stack: push(1); push(2); push(3); pop(); push(4); pop(); pop();. What does the stack contain at the end?
push(1) -> [1]. push(2) -> [1,2]. push(3) -> [1,2,3]. pop() removes 3 -> [1,2]. push(4) -> [1,2,4]. pop() removes 4 -> [1,2]. pop() removes 2 -> [1]. Final stack: [1].
Q11
After the sequence push(10); push(20); push(30); pop(); push(40);, what does size() return?
push adds three elements (size 3), pop removes one (size 2), then push adds one more (size 3). The stack ends with 3 elements.
Q12
Trace this code. What is the final value of sum?
std::stack<int> s;
for (int i = 1; i <= 5; ++i) s.push(i);
int sum = 0;
while (!s.empty()) {
    int t = s.top(); s.pop();
    if (t % 2 == 0) s.push(t / 2);
    else sum += t;
}
Stack after the loop (bottom to top): [1,2,3,4,5]. Popping and applying the rule step by step: pop 5 (odd, sum=5). pop 4 (even, push 2). pop 2 (even, push 1). pop 1 (odd, sum=6). pop 3 (odd, sum=9). pop 2 (even, push 1). pop 1 (odd, sum=10). pop 1 (odd, sum=11). Final sum = 11.
Q13
What does this code print?
#include <iostream>
#include <stack>
int main() {
    std::stack<int> s;
    s.push(10);
    s.push(20);
    std::cout << s.top() << " ";
    s.pop();
    s.push(30);
    s.pop();
    std::cout << s.top();
    return 0;
}
push(10), push(20): stack is [10, 20]. top() prints 20. pop() removes 20: stack is [10]. push(30): stack is [10, 30]. pop() removes 30: stack is [10]. top() prints 10. Final output: 20 10.
Q14
What is the output of this code?
#include <iostream>
#include <stack>
int main() {
    std::stack<int> s;
    for (int i = 1; i <= 3; ++i) s.push(i * i);
    int sum = 0;
    while (!s.empty()) {
        sum += s.top();
        s.pop();
    }
    std::cout << sum;
}
The values pushed are 1, 4, and 9 (1*1, 2*2, 3*3). Popping and adding all of them gives 1 + 4 + 9 = 14.
Q15
What happens if you call pop() on an empty std::stack in C++?
std::stack does not check whether it is empty before popping. Calling pop() (or top()) on an empty stack is undefined behavior — the program may crash or produce garbage. It is the caller's job to check empty() first.
Q16
What is the difference between top() and pop() in std::stack?
top() returns a reference to the top element but leaves it on the stack. pop() removes the top element but does not return its value — that is why code usually calls top() first to read the value, then pop() to remove it.
Q17
What is the main disadvantage of implementing a Stack using a singly linked list instead of an array?
A linked-list stack never overflows because it grows as needed, but every node must store an extra pointer (8 bytes on a 64-bit system) along with the data.
Q18
Compared to an array-based stack, what is the main advantage of a linked-list-based stack?
An array-based stack has a fixed capacity and can overflow. A linked-list stack allocates a new node for every push, so it keeps growing until memory itself runs out. The trade-off is extra pointer memory per node and weaker cache locality.
Q19
This function checks whether parentheses are balanced. What does it return for the input "(()))"?
#include <stack>
#include <string>
bool check(std::string s) {
    std::stack<char> st;
    for(char c : s) {
        if(c == '(') st.push(c);
        else if(c == ')') {
            if(st.empty()) return false;
            st.pop();
        }
    }
    return st.empty();
}
The string has two '(' characters, which get pushed. The first two ')' characters pop them, leaving the stack empty. The third ')' finds an empty stack, so the function returns false right away.
Q20
A stack-based bracket checker reads the string {[()]} from left to right. How many push operations happen before the first pop?
Reading left to right: '{' is pushed, '[' is pushed, '(' is pushed — three pushes in a row. The next character ')' is a closing bracket, which causes the first pop. So 3 pushes happen before the first pop.
Q21
A balanced-bracket checker reads the string ( [ { } ] ) ). It pushes each opening bracket and pops on each closing bracket, checking that the popped bracket matches. At which character does the checker first report an error?
Trace: '(' push, '[' push, '{' push, '}' pops '{' (match), ']' pops '[' (match), ')' pops '(' (match) — the stack is now empty. The final ')' arrives with nothing left to pop, so the checker reports an error there.
Q22
When using a stack to check that XHTML tags are properly nested, which situation signals a nesting error?
Every closing tag must match the most recently pushed opening tag. If the popped tag is different, or the stack is empty when we try to pop, the tags are not properly nested.
Q23
Using a stack, evaluate this postfix expression: 10 4 2 / + 5 *. What is the result?
Push 10, 4, 2. '/': pop 2 and 4, compute 4/2 = 2, push 2. '+': pop 2 and 10, compute 10+2 = 12, push 12. Push 5. '*': pop 5 and 12, compute 12*5 = 60.
Q24
Convert the infix expression (A + B) * C - D to postfix.
First convert (A + B) to A B +. Then multiply by C: A B + C *. Finally subtract D: A B + C * D -.
Q25
Which data structure is commonly used to implement the Back and Forward buttons in a web browser?
Browsers typically use two stacks: one for Back and one for Forward. Visiting a new page pushes the current page onto the Back stack and clears the Forward stack.
Q26
Calling a recursive function with too much recursion depth (for example, no base case, or a very large input) can crash a program with a 'stack overflow' error. Why does this happen?
Every function call, including each recursive call, pushes a new frame onto the program's call stack to store local variables and the return address. If recursion goes too deep, the call stack runs out of space, causing a stack overflow crash.
Q27
A recursive function rev(s, i) prints s[i] after calling rev(s, i+1). For the input "abc" starting at i = 0, in what order are the characters printed?
The calls go rev(0) -> rev(1) -> rev(2) -> rev(3) (base case) before anything prints. On the way back out, i=2 prints 'c' first, then i=1 prints 'b', then i=0 prints 'a'. This mirrors how a stack unwinds: last in, first out.
Q28
In a plain stack with no extra data structure, what is the time complexity of finding the minimum element among N elements?
A plain stack only lets us access the top element. To find the minimum, we would need to pop every element to look at it, which takes O(N) time.
Q29
A MinStack keeps a second, auxiliary stack that always stores the minimum value seen so far. We perform push(5), push(3), push(7), then call getMin(). What does getMin() return?
The auxiliary min-stack tracks the smallest value at each step: after push(5) it is [5]; after push(3) it is [5,3] because 3 is smaller; after push(7) it stays [5,3] because 7 is not smaller than 3. getMin() reads the top of the auxiliary stack, which is 3. This trick makes getMin() run in O(1).
Q30
We implement a Queue using two stacks, inStack and outStack. Across a long sequence of operations, what is the amortized time complexity of dequeue()?
Each element moves from inStack to outStack at most once during its lifetime. A single dequeue() can cost O(N) when outStack is empty and needs refilling, but that cost is spread across the many O(1) dequeues that follow. This gives O(1) amortized time.
