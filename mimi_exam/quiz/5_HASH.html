05. Hash Tables

Q1
Which collision resolution strategy uses a linked list at each table slot to store multiple colliding entries?
Separate Chaining (Open Hashing) allocates a list or bucket array for each table index. Colliding keys are simply appended to the list.
Q2
Using Modulo-Division hashing ($H(x) = x \pmod{13}$) and Linear Probing ($h_i(x) = (x+i)\pmod{13}$), if index 7 is occupied by key 85, where does key 189 map? (Note: $189 \pmod{13} = 7$)
$H(189) = 189 \pmod{13} = 7$ (Collision). Linear probing tests index 8: $(7+1) \pmod{13} = 8$.
Q3
What is the mathematical probe sequence formula for Quadratic Probing on the $i$-th collision?
Quadratic Probing increases the search step quadratically with collision iteration index: $h_i(x) = (H(x) + i^2) \pmod N$.
Q4
Why is physical entry deletion incorrect in Open Addressing hash maps?
Open addressing lookup stops probing when finding an empty slot. If you physically delete a node, lookups for later elements in that probe path will fail.
Q5
What is the primary purpose of Rehashing in a Hash Table?
Rehashing creates a larger table and re-inserts all existing elements. This reduces collision density.
Q6
What is the load factor $\alpha$ of a hash table with M slots storing N elements?
The load factor $\alpha$ is the average number of elements per slot: $\alpha = N / M$.
Q7
What is 'Primary Clustering' in linear probing?
In linear probing, any collision creates a run of adjacent occupied slots, widening the cluster.
Q8
In Double Hashing $h_i(x) = (H(x) + i \cdot f(x)) \pmod N$, why must the second hash function $f(x)$ return a value relatively prime to the table size $N$?
If $f(x)$ is relatively prime to $N$, the probe sequence is guaranteed to visit all $N$ slots before repeating.
Q9
What is a defining feature of a Cryptographic Hash Function?
Cryptographic hash functions are designed to be one-way (pre-image resistant) and collision-resistant.
Q10
What is the worst-case time complexity of inserting an element in a Hash Table of size N if all elements hash to the same index?
If all elements hash to the same slot, the hash table degrades to a linear list or probed array structure, yielding $O(N)$ time.
Q11
What does a Hash Function do?
A hash function takes a key input and computes an integer index representing where that key's record should be stored in the hash table array.
Q12
What is the primary drawback of Quadratic Probing?
While quadratic probing avoids primary clustering (runs of occupied slots), keys that map to the same initial index still follow the same probe sequence (secondary clustering).
Q13
What is a hash collision?
A collision occurs when $key_1 \neq key_2$ but $H(key_1) == H(key_2)$, mapping both to the same array bucket.
Q14
In Separate Chaining, what is the average search time complexity if the load factor $\alpha$ is kept constant?
In separate chaining, the average chain length is $\alpha$. If $\alpha$ is bounded by a constant, search takes $O(1 + \alpha) = \mathcal{O}(1)$ average time.
Q15
Which of the following is NOT a valid collision resolution technique?
Inorder traversal is a tree traversal method, not a collision resolution probe method for hash tables.
Q16
Evaluate this hash function. Where does the key 10 map under a hash table of size 11?
int hash(int key) {
    return (key * 3 + 5) % 11;
}
Executing the arithmetic: (10 * 3 + 5) % 11 = 35 % 11. Since 11 * 3 = 33, 35 - 33 leaves a remainder of 2. Thus, the index is 2.
Q17
Consider a hash table of size 7 initialized to all 0s (empty slots). If we insert keys 10 and 17 in order using the logic below, where is key 17 stored?
void insert(int key) {
    int idx = key % 7;
    while(table[idx] != 0) {
        idx = (idx + 1) % 7;
    }
    table[idx] = key;
}
1) 10 % 7 = 3. Slot 3 is empty, so table[3] = 10. 2) 17 % 7 = 3. Slot 3 is occupied (collision). Probing next index: (3+1)%7 = 4. Slot 4 is empty, so table[4] = 17.
Q18
Continuing the Double Hashing trace from the lecture notes (N=11, R=7, primary hash H(K)=K mod 11, secondary hash f(K)=7-(K mod 7)), after inserting 75 (slot 9) and 152 (collides at slot 9, resolves to slot 0), where does 171 land? (171 mod 11 = 6, no collision)
H(171) = 171 mod 11 = 6. Slot 6 is currently empty (only slots 9 and 0 are occupied so far), so 171 is placed directly at slot 6 with no probing needed.
Q19
Continuing the same double hashing trace (N=11, R=7; occupied so far: slot 9 has 75, slot 0 has 152, slot 6 has 171), where does 38 land? (38 mod 11 = 5)
H(38) = 38 mod 11 = 5. Slot 5 is empty, so 38 is inserted directly at slot 5 with zero probes.
Q20
Continuing the same trace (N=11, R=7; occupied: slot 9=75, slot 0=152, slot 6=171, slot 5=38), insert 211. Since 211 mod 11 = 2, where does it land?
H(211) = 211 mod 11 = 2, which is currently empty, so 211 is placed directly at slot 2.
Q21
Continuing the same trace (occupied: 9=75, 0=152, 6=171, 5=38, 2=211), insert 18. 18 mod 11 = 7 — where does it land?
H(18) = 18 mod 11 = 7, which is empty, so 18 goes directly into slot 7 with no probing required.
Q22
Finishing the double hashing trace (N=11, R=7; occupied: 9=75, 0=152, 6=171, 5=38, 2=211, 7=18), insert 189. Since 189 mod 11 = 2 collides with 211, and the secondary hash is f(189) = 7 - (189 mod 7) = 7 - 0 = 7, which slot does 189 finally occupy?
Probe with step f=7: i=1 -> (2+7) mod 11 = 9, occupied by 75 (collision). i=2 -> (2+14) mod 11 = 5, occupied by 38 (collision). i=3 -> (2+21) mod 11 = 23 mod 11 = 1, which is empty. 189 is placed in slot 1.
Q23
Using Modulo-Division hashing with table size N=13 and Linear Probing, insert keys in order: 27, 40, 14. Since 27 mod 13 = 1, 40 mod 13 = 1 (collision), and 14 mod 13 = 1 (collision), which slots do they end up in respectively?
27 hashes to slot 1 (empty, placed directly). 40 also hashes to slot 1 (occupied), linear probing tries (1+1)%13=2 (empty) -> placed at slot 2. 14 also hashes to slot 1 (occupied), tries slot 2 (occupied by 40), tries (1+2)%13=3 (empty) -> placed at slot 3.
Q24
A hash table of size 7 uses H(K) = K mod 7 with Separate Chaining. After inserting 10, 17, 24, 3, how many elements are in the chain at slot 3?
10 mod 7 = 3, 17 mod 7 = 3, 24 mod 7 = 3, and 3 mod 7 = 3 — all four keys hash to the same slot, so the chain at slot 3 holds all 4 elements.
Q25
Using Quadratic Probing with N=11, if a key hashes to H(K)=4 and collides, what is the slot examined at the 2nd collision (i=2)?
Quadratic probing formula: h_i(K) = (H(K) + i^2) mod N. At i=2: (4 + 4) mod 11 = 8.
Q26
A hash table has 8 slots and currently stores 6 elements using Separate Chaining. What is the load factor λ?
Load factor λ = number of elements / table size = 6 / 8 = 0.75.
Q27
In Open Addressing with maxLoadFactor = 0.5, a table of size 11 currently holds 5 elements. If one more element is inserted (making 6), does a rehash trigger before or after this insertion, and to what approximate new size (next prime after doubling)?
After the 6th insertion, load factor = 6/11 ≈ 0.545, which exceeds the 0.5 threshold, triggering a rehash. The new capacity is the next prime number ≥ (11*2)=22, which is 23.
Q28
What is the output of this hash-based frequency counting trace?
#include <iostream>
#include <unordered_map>
#include <string>
int main() {
    std::unordered_map<char, int> freq;
    std::string s = "banana";
    for (char c : s) freq[c]++;
    std::cout << freq['a'] << " " << freq['n'] << " " << freq['b'];
}
In 'banana': b appears 1 time, a appears 3 times (positions 1,3,5), n appears 2 times (positions 2,4). freq['a']=3, freq['n']=2, freq['b']=1. Output: '3 2 1'.
Q29
Trace the Two Sum hash map algorithm on nums=[3, 2, 4], target=6. As we iterate left to right and check target - nums[i] against previously seen numbers before inserting the current one, at which index do we find a match?
i=0 (val=3): complement=6-3=3, not seen yet, store 3->0. i=1 (val=2): complement=6-2=4, not seen, store 2->1. i=2 (val=4): complement=6-4=2, and 2 WAS seen at index 1 — match found at index 2.
Q30
Why must the secondary hash function f(K) in Double Hashing never evaluate to 0 for any key?
The probe sequence is h_i(K) = (H(K) + i*f(K)) mod N. If f(K)=0, every term i*f(K)=0, so h_i(K) is the same slot for all i — the probing never advances, causing an infinite loop whenever that first slot is already occupied by a different key.
