05. Hash Tables

Q1
What does a Hash Function do?
A hash function takes a key as input and computes an integer index representing where that key's record should be stored in the hash table's array.
Q2
In Direct Hashing, how is a key mapped to a table index?
Direct hashing uses the key itself, sometimes with a constant offset, as the array index. It only works well when the range of possible key values is small enough to fit the table, since no compression step is applied.
Q3
In Subtraction Hashing, how is the index computed?
Subtraction hashing subtracts the smallest possible key value from the key, shifting the whole range of keys down so the smallest key maps to index 0. This helps when keys form a contiguous range that doesn't start at 0.
Q4
What does Digit-Extraction hashing do?
Digit-extraction hashing picks out digits from particular positions in the key, for example the 2nd and 4th digits, and combines them to form the table index. It works well when those specific digit positions are fairly evenly distributed across different keys.
Q5
What does the Mid-Square hashing method do?
Mid-square hashing squares the key, then takes digits from the middle of the squared result as the index. Those middle digits tend to depend on most of the original key's digits, which usually spreads keys out better than looking at just a few digits directly.
Q6
In the Folding method of hashing, the key is split into equal-sized parts, which are then added together to form the index. What is the difference between shift folding and boundary folding?
In shift folding, each part is added in its original left-to-right orientation. In boundary folding, alternating parts are reversed, as if folding a strip of paper at each boundary, before adding, which can spread each digit's influence more evenly across the result.
Q7
Evaluate this hash function. Where does the key 10 map in a hash table of size 11?
int hash(int key) {
    return (key * 3 + 5) % 11;
}
Computing the arithmetic: (10 * 3 + 5) % 11 = 35 % 11. Since 11 * 3 = 33, 35 - 33 leaves a remainder of 2. So the index is 2.
Q8
What is a hash collision?
A collision occurs when two different keys (key1 != key2) still map to the same index — H(key1) == H(key2) — placing both in the same slot.
Q9
Which collision resolution strategy uses a linked list at each table slot to store multiple colliding entries?
Separate Chaining (Open Hashing) allocates a list, or bucket, for each table index. Colliding keys are simply appended to that slot's list.
Q10
What is 'Primary Clustering' in linear probing?
In linear probing, any collision creates a run of adjacent occupied slots. As that run grows, it becomes even more likely to be hit by future keys, widening the cluster further.
Q11
What is the primary drawback of Quadratic Probing?
Quadratic probing avoids primary clustering (long runs of occupied slots), but keys that map to the same initial index still follow the exact same probe sequence as each other — this is secondary clustering.
Q12
Which of the following is NOT a valid collision resolution technique?
Inorder traversal is a tree traversal method, not a collision resolution technique for hash tables.
Q13
Using Modulo-Division hashing (H(x) = x mod 13) and Linear Probing (h_i(x) = (x+i) mod 13), if index 7 is occupied by key 85, where does key 189 map? (189 mod 13 = 7)
H(189) = 189 mod 13 = 7, which collides with 85 already there. Linear probing then tries index 8: (7+1) mod 13 = 8.
Q14
Consider a hash table of size 7, initialized to all empty slots. Inserting keys 10 and 17 in order using linear probing (idx = key % 7, advancing by 1 on collision), where does key 17 end up?
10 % 7 = 3. Slot 3 is empty, so 10 is placed there. 17 % 7 = 3, which is now occupied (collision). Probing the next index: (3+1) % 7 = 4, which is empty, so 17 is placed at index 4.
Q15
A hash table of size 7 uses H(K) = K mod 7 with Separate Chaining. After inserting 10, 17, 24, 3, how many elements are in the chain at slot 3?
10 mod 7 = 3, 17 mod 7 = 3, 24 mod 7 = 3, and 3 mod 7 = 3 — all four keys hash to the same slot, so the chain at slot 3 holds all 4 elements.
Q16
What is the mathematical probe sequence formula for Quadratic Probing on the i-th collision?
Quadratic Probing increases the search step quadratically with the collision index: h_i(x) = (H(x) + i^2) mod N.
Q17
Using Quadratic Probing with N=11, if a key hashes to H(K)=4 and collides, what slot is examined at the 2nd collision (i=2)?
Quadratic probing formula: h_i(K) = (H(K) + i^2) mod N. At i=2: (4 + 4) mod 11 = 8.
Q18
In Double Hashing, h_i(x) = (H(x) + i * f(x)) mod N, why must the second hash function f(x) return a value relatively prime to the table size N?
If f(x) is relatively prime to N, the probe sequence is guaranteed to cycle through all N slots before it repeats any slot.
Q19
Why must the secondary hash function f(K) in Double Hashing never evaluate to 0 for any key?
The probe sequence is h_i(K) = (H(K) + i*f(K)) mod N. If f(K)=0, every term i*f(K) is also 0, so h_i(K) is the same slot for every i — the probe never advances, causing an infinite loop whenever that first slot is already occupied by a different key.
Q20
Why is physically deleting an entry incorrect in Open Addressing hash tables?
Open-addressing lookups stop probing as soon as they hit an empty slot. If you physically delete an entry (leaving an empty slot) that other keys had to probe past, lookups for those later keys will incorrectly stop early and report 'not found'.
Q21
What is the primary purpose of Rehashing in a Hash Table?
Rehashing creates a larger table (typically the next prime after roughly doubling) and re-inserts all existing elements into it. This lowers the load factor and reduces collision density.
Q22
What is the load factor of a hash table with M slots storing N elements?
The load factor is the average number of elements per slot: load factor = N / M.
Q23
A hash table has 8 slots and currently stores 6 elements using Separate Chaining. What is the load factor?
Load factor = number of elements / table size = 6 / 8 = 0.75.
Q24
In Open Addressing with a maximum load factor of 0.5, a table of size 11 currently holds 5 elements. If one more element is inserted (making 6), does a rehash trigger, and to what approximate new size?
After the 6th insertion, the load factor is 6/11 ≈ 0.545, which exceeds the 0.5 threshold, triggering a rehash. The new capacity is the next prime number at or above 11*2=22, which is 23.
Q25
What is the worst-case time complexity of inserting an element into a Hash Table of size N if all elements hash to the same index?
If every element hashes to the same slot, the hash table degrades into a plain linear list (or a fully-probed array), giving O(N) time.
Q26
In Separate Chaining, what is the average search time complexity if the load factor is kept roughly constant?
In separate chaining, the average chain length equals the load factor. If the load factor is bounded by a constant, average search time is O(1 + load factor) = O(1).
Q27
Using std::unordered_map<std::string,int> stock;, if we call stock["apple"] to check the count, but "apple" was never inserted before, what value do we get?
For std::unordered_map, operator[] on a missing key automatically creates that key with a default-constructed value, 0 for int, and inserts it into the map. This is exactly why a frequency counter like freq[c]++ works correctly the very first time a key is seen.
Q28
You are building a warehouse stock tracker: ADD <item> increases that item's count by 1, inserting it with count 1 if it's new. Using std::unordered_map<std::string,int> stock;, which single line correctly implements ADD?
stock[item]++ relies on operator[] auto-creating the entry with value 0 the first time an item is seen, then incrementing it to 1. On every later ADD for the same item, it simply increments the existing count — one line correctly handles both the new-item and existing-item cases.
Q29
What is the output of this hash-based frequency counting trace?
#include <iostream>
#include <unordered_map>
#include <string>
int main() {
    std::unordered_map<char, int> freq;
    std::string s = "banana";
    for (char c : s) freq[c]++;
    std::cout << freq['a'] << " " << freq['n'] << " " << freq['b'];
}
In 'banana': b appears 1 time, a appears 3 times, n appears 2 times. freq['a']=3, freq['n']=2, freq['b']=1. Output: '3 2 1'.
Q30
Trace the Two Sum hash map algorithm on nums=[3, 2, 4], target=6. As we iterate left to right, checking target - nums[i] against previously seen numbers before inserting the current one, at which index do we find a match?
i=0 (val=3): complement=6-3=3, not seen yet, store 3->0. i=1 (val=2): complement=6-2=4, not seen, store 2->1. i=2 (val=4): complement=6-4=2, and 2 WAS seen at index 1 — a match is found at index 2.
