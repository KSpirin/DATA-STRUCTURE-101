01-A. C++ Basics & Memory Management

Q1
Why must the preprocessor guard directive #ifndef SINGLE_LIST_H be placed at the top of header files?
Including the same header multiple times causes duplicate class or variable definitions. Guards like #ifndef, #define, and #endif prevent the definition block from being compiled twice.
Q2
Which of the following correctly forms a header guard?
The correct order is: #ifndef checks that the guard macro is not yet defined, #define immediately defines it, then the declarations follow, and #endif closes the conditional at the end of the file.
Q3
A header file uses #ifndef and #define for a header guard, but the programmer forgets to add the matching #endif. What happens?
#ifndef opens a conditional block that must be closed with #endif. Without it, the preprocessor may treat the rest of the file, or even the rest of whatever gets included afterward, as still being inside that conditional, usually causing a compiler error or unexpected behavior.
Q4
Given the preprocessor performs pure text substitution with no syntax checking, what is printed?
#include <iostream>
#define SQUARE(x) x * x
int main() {
    std::cout << SQUARE(2 + 3);
}
Textual substitution gives 2 + 3 * 2 + 3, which by operator precedence evaluates as 2 + (3*2) + 3 = 2+6+3 = 11, not 25. This is why function-like macros are dangerous without parentheses.
Q5
A student forgets a header guard and includes 'Node.h' from two different .cpp translation units linked into the same executable. What is the most likely resulting error?
Without a header guard, if the header defines (not just declares) functions or variables and is included in multiple .cpp files, each translation unit emits its own copy of the symbol. The linker then reports a 'multiple definition' error when combining the object files.
Q6
What is the difference between #include <iostream> and #include "myheader.h"?
Angle brackets tell the preprocessor to look in the compiler's standard system directories, used for standard libraries like iostream. Quotes tell it to look in the current directory first, used for your own local header files.
Q7
Trace the following namespace resolution. What is printed?
#include <iostream>
namespace lab {
    int n = 4;
}
int n = 10;
int main() {
    std::cout << n << " " << lab::n;
}
The unqualified n inside main() refers to the global n (10). lab::n explicitly accesses the namespace-scoped n (4). Output: '10 4'.
Q8
Why is writing using namespace std; at the top of a header file generally considered bad practice?
A using directive in a header file affects every source file that includes it, pulling all of std's names into the global namespace everywhere. This raises the risk of naming collisions, which is why it is safer to write std:: explicitly, or keep using namespace std; local to a small scope.
Q9
Consider the code: int x = 10; int& ref = x; ref += 5; x *= 2;. What is the value of ref after these operations?
A reference is an alias. Adding 5 to ref changes x to 15. Then multiplying x by 2 changes it to 30. Since ref aliases x, it evaluates to 30.
Q10
Once a C++ reference is initialized to refer to a variable, can it later be made to refer to a different variable?
Unlike a pointer, a reference cannot be 're-seated' to refer to something else after initialization. Assigning through a reference (ref = something;) changes the value of the variable it refers to — it does not change what the reference refers to.
Q11
What does this code print?
void swap(int& a, int& b) {
    int t = a; a = b; b = t;
}
int main() {
    int x = 3, y = 8;
    swap(x, y);
    std::cout << x << " " << y;
}
Because a and b are references to x and y, swapping a and b inside the function directly swaps the original x and y. After the call, x = 8 and y = 3.
Q12
What is the output of the following C++ code?
#include <iostream>
void modify(int* a, int& b) {
    *a += 5;
    b *= 2;
}
int main() {
    int x = 10, y = 20;
    modify(&x, y);
    std::cout << (x + y);
    return 0;
}
Inside modify, x is modified via pointer dereference (*a += 5) to 15. y is passed by reference, so b *= 2 modifies y to 40. The sum 15 + 40 equals 55.
Q13
Trace pointer arithmetic. What does this print?
#include <iostream>
int main() {
    int arr[4] = {10, 20, 30, 40};
    int* p = arr;
    p += 2;
    std::cout << *p << " " << *(p - 1);
}
p starts at arr[0]. p += 2 advances it by 2 elements, not bytes, to arr[2] = 30. *(p-1) is arr[1] = 20. Output: '30 20'.
Q14
Given int* pi and char* pc, both currently pointing to the same address, what happens after pi++ and pc++ (assuming sizeof(int) == 4)?
Pointer arithmetic is scaled by the size of the pointed-to type. Incrementing an int* moves it forward by sizeof(int) bytes (4), while incrementing a char* moves it forward by sizeof(char) byte (1).
Q15
Which C++ operator is used to deallocate memory previously allocated with new for a single object?
For single objects allocated with new, use delete. For array allocations like new Type[N], use delete[].
Q16
Which of the following describes the difference between delete and delete[]?
For arrays allocated via new Type[N], delete[] ensures the destructor runs for all N objects in the array. Plain delete only runs it for the first, and using the wrong one is undefined behavior.
Q17
What is the consequence of executing: int* p = new int(5); delete p; std::cout << *p;?
Deleting a pointer deallocates the memory it points to. Accessing it afterward through a dangling pointer results in Undefined Behavior, which could crash the program or output garbage values.
Q18
What is the rule for matching new and delete in C++?
new and delete are a matched pair for single objects; new[] and delete[] are a matched pair for arrays. Mixing them, for example calling delete on memory from new[], is undefined behavior.
Q19
What is a 'memory leak' in a C++ program?
A memory leak happens when a program loses all references to memory it allocated on the heap, for example by overwriting the only pointer to it, without calling delete first. That memory stays reserved and unusable until the program ends.
Q20
If class ClassA declares class ClassB to be a friend (friend class ClassB; inside ClassA), which of the following is true?
Friendship is one-way: ClassA declaring ClassB as a friend allows ClassB to access ClassA's private members, but not the reverse. Friendship is also neither inherited nor transitive.
Q21
What is the primary difference between a C++ struct and a C++ class?
In C++, the only real difference is that a struct defaults to public member visibility and inheritance, while a class defaults to private. Both can have member functions, constructors, and templates.
Q22
What is printed when a template function is instantiated with two different types?
#include <iostream>
template <typename T>
T sqr(T x) { return x * x; }
int main() {
    std::cout << sqr(3) << " " << sqr(2.5);
}
The compiler instantiates sqr and sqr separately at compile time, based on the argument types. sqr(3) -> 9, sqr(2.5) -> 6.25.
Q23
Given a class template template <typename Type> class Complex { ... };, how do you create an instance that stores double values?
To instantiate a class template with a specific type, the type goes in angle brackets right after the class name. Complex z(3.7, 4.2); tells the compiler to generate a version of Complex that stores double values.
Q24
Trace this loop. What is arr[3] after execution?
int arr[5];
arr[0] = 1;
for (int i = 1; i < 5; ++i) {
    arr[i] = 2 * arr[i - 1] + 1;
}
arr[0]=1, arr[1]=2*1+1=3, arr[2]=2*3+1=7, arr[3]=2*7+1=15.
Q25
What is the key difference between a while loop and a do-while loop in C++?
A while loop checks its condition before the first execution, so its body might never run. A do-while loop checks its condition after running the body, so the body always executes at least once.
Q26
Given the input line 7 3, what values do x and y hold after this code runs?
int x, y;
std::cin >> x >> y;
cin >> reads whitespace-separated values in order. The first value, 7, is stored in x; the second value, 3, is stored in y.
Q27
What is printed by this operator chaining?
#include <iostream>
int sqr(int x){ return x*x; }
int main(){
    std::cout << "val=" << sqr(3) << std::endl;
}
cout << is evaluated left to right: ((cout << "val=") << sqr(3)) << endl. sqr(3) evaluates to 9, so it prints 'val=9'.
Q28
Why does an expression like cout << a << b << c; work correctly in C++?
operator<< is overloaded to return a reference to the ostream it was called on, usually cout itself. That lets the result of one << be immediately used as the left-hand side of the next <<, allowing the whole chain to work left to right.
Q29
Trace the recursion. What value does func(4) return?
int func(int x) {
    if (x < 1) return 0;
    return x + func(x - 1);
}
func(4)=4+func(3), func(3)=3+func(2), func(2)=2+func(1), func(1)=1+func(0), func(0)=0. Summing back: 1, 3, 6, 10. func(4)=10.
Q30
Trace this static local variable across multiple calls. What is printed?
#include <iostream>
void counter() {
    static int count = 0;
    count++;
    std::cout << count << " ";
}
int main() {
    counter();
    counter();
    counter();
}
A static local variable is initialized only once and keeps its value between function calls, unlike a normal local variable, which is re-created and re-initialized every call. Each call increments the same persistent count: 1, then 2, then 3.
