02. Stack ADT

Q1
What is the postfix (Reverse Polish) representation of the infix expression: A + B * (C - D) / E?
Following operator precedence: 1) `(C - D)` -> `C D -`. 2) Multiply by `B` -> `B C D - *`. 3) Divide by `E` -> `B C D - * E /`. 4) Add `A` -> `A B C D - * E / +`.
Q2
For a stack implemented using a fixed-size array of capacity N with the top-index tracking variable top initialized to 0 (where data is pushed into index top and then top is incremented), what represents the stack full condition?
If top starts at 0 and increments after pushing, it equals the current size. The stack is full when size reaches capacity: top == N.
Q3
Which of the following describes the operational behavior of a Stack?
Stacks follow Last-In, First-Out (LIFO) behavior. Insertions and removals are only performed at one end (the top).
Q4
Using a stack, what is the output of evaluating the following postfix expression: 10 4 2 / + 5 *?
1) Push 10, 4, 2. 2) `/` pop 2, 4 -> 4/2 = 2. Push 2. 3) `+` pop 2, 10 -> 10+2 = 12. Push 12. 4) Push 5. 5) `*` pop 5, 12 -> 12 * 5 = 60.
Q5
When parsing XHTML tags with a stack, which condition indicates a syntax nesting error?
Nesting requires that any closing tag must match the most recently pushed opening tag. If the popped tag doesn't match, or the stack is empty during a pop, the tags are mismatched.
Q6
Which data structure is typically used to implement the 'Back' and 'Forward' navigation history in web browsers?
Web browsers use two stacks: a 'Back' stack and a 'Forward' stack. Clicking a link pushes the current page to the 'Back' stack and clears the 'Forward' stack.
Q7
What is the time complexity to retrieve the minimum element from a standard, non-auxiliary Stack ADT of size N?
A standard stack only exposes the top element. Finding the minimum requires popping all elements to inspect them, taking linear $\mathcal{O}(N)$ time.
Q8
Which of the following defines a 'Monotonic Decreasing Stack'?
A Monotonic Decreasing Stack maintains its elements in strictly decreasing order from bottom to top (each pushed element is smaller than the one below it).
Q9
Convert the Prefix expression * + A B - C D to Postfix.
Prefix `* + A B - C D` evaluates as: 1) `+ A B` -> `(A+B)`. 2) `- C D` -> `(C-D)`. 3) `*` applied to results -> `(A+B) * (C-D)`, which in postfix is `A B + C D - *`.
Q10
What occurs when an application attempts to push an element onto an array-based stack that has reached its capacity limit?
Pushing onto a stack that has exceeded its storage capacity triggers a Stack Overflow condition.
Q11
In an infix-to-postfix conversion algorithm using a stack, what is done when an operator is parsed?
Operators are stored on the stack. To maintain precedence, before pushing a new operator, we must pop and print any stack operators that have greater or equal precedence.
Q12
What is the primary drawback of using a singly linked list to implement a Stack ADT?
A linked list stack grows dynamically (no overflow), but every node incurs pointer overhead (8 bytes on 64-bit systems) in addition to the data storage.
Q13
Which stack-based traversal algorithm matches Depth-First Search?
Preorder and DFS traversals utilize a LIFO Stack structure to track nodes along a single path before backtracking.
Q14
What is the prefix representation of the infix expression: A * B + C?
1) `A * B` -> `* A B`. 2) Add `C` -> `+ * A B C`.
Q15
If a stack contains elements [X, Y, Z] (Z is top) and we perform: push(W), pop(), pop(), what is the top element?
1) Initial: `[X, Y, Z]`. 2) Push W -> `[X, Y, Z, W]`. 3) Pop -> pops W, stack becomes `[X, Y, Z]`. 4) Pop -> pops Z, stack becomes `[X, Y]`. Top is Y.
Q16
Determine the output of the following stack operations:
#include <iostream>
#include <stack>
int main() {
    std::stack<int> s;
    s.push(10);
    s.push(20);
    std::cout << s.top() << " ";
    s.pop();
    s.push(30);
    s.pop();
    std::cout << s.top();
    return 0;
}
1) Push 10, push 20. 2) s.top() prints 20. 3) s.pop() removes 20 (stack is [10]). 4) s.push(30) makes stack [10, 30]. 5) s.pop() removes 30 (stack is [10]). 6) s.top() prints 10. Output: '20 10'.
Q17
A parsing program executes this function. What does it return for the string "(()))"?
#include <stack>
#include <string>
bool check(std::string s) {
    std::stack<char> st;
    for(char c : s) {
        if(c == '(') st.push(c);
        else if(c == ')') {
            if(st.empty()) return false;
            st.pop();
        }
    }
    return st.empty();
}
The string has two open parentheses, which are pushed. The first two close parentheses pop them, leaving the stack empty. The third close parenthesis encounters an empty stack (st.empty() is true) and returns false.
Q18
Evaluate this postfix expression step by step. What is the final result of 6 2 3 + - 4 *?
Push 6, 2, 3 (stack: [6,2,3]). '+': pop 3, pop 2, push 2+3=5 (stack: [6,5]). '-': pop 5, pop 6, push 6-5=1 (stack: [1]). Push 4 (stack: [1,4]). '*': pop 4, pop 1, push 1*4=4. Final result: 4.
Q19
Trace this expression evaluation using a stack: 4 5 6 * + 3 -. What is the final value?
Push 4,5,6. '*': pop 6,5 -> 5*6=30, push (stack:[4,30]). '+': pop 30,4 -> 4+30=34, push (stack:[34]). Push 3 (stack:[34,3]). '-': pop 3,34 -> 34-3=31.
Q20
Convert the infix expression (A + B) * C - D to postfix.
1) (A+B) -> A B +. 2) Multiply by C -> A B + C *. 3) Subtract D -> A B + C * D -.
Q21
Simulate infix-to-postfix conversion for A * (B + C) using an operator stack. Immediately after reading the ')' token, what has been output so far and what remains on the stack?
Reading A outputs 'A'. '*' is pushed (stack: [*]). '(' is pushed (stack: [*, (]). B outputs 'A B'. '+' is pushed since it's inside the parentheses (stack: [*, (, +]). C outputs 'A B C'. On ')', pop and output operators until '(' is found: pop '+' -> output 'A B C +', then discard the '('. The stack now holds only [*], which waits to be popped at the end.
Q22
A stack-based bracket checker processes the string {[()]}. How many push operations occur in total before the first pop?
Reading left to right: '{' push, '[' push, '(' push — three consecutive pushes. The next character ')' is a closing bracket, which triggers the first pop (matched against '('). So 3 pushes occur before the first pop.
Q23
Given a stack-based array implementation where Array[0] stores the capacity (slide convention) and data occupies indices 1..top, after executing push(5); push(8); pop(); push(3); on an initially empty stack (top=0), what is the final value of top and Array[top]?
push(5): top=1, Array[1]=5. push(8): top=2, Array[2]=8. pop(): returns Array[2]=8, top=1. push(3): top=2, Array[2]=3. Final: top=2, Array[top]=3.
Q24
Using two stacks (inStack and outStack) to implement a Queue, what is the amortized time complexity of dequeue() across a long sequence of operations?
Each element is moved from inStack to outStack (reversing order) at most once over its lifetime. Although a single dequeue can be O(N) when outStack is empty and must be refilled, that cost is spread over the many O(1) dequeues that follow, giving O(1) amortized time.
Q25
Trace the monotonic stack algorithm for 'Daily Temperatures' on input [73, 74, 75, 71, 69]. What is answer[0] (days until a warmer temperature after index 0)?
Index 0 (73) is immediately followed by index 1 (74), which is warmer. So it only takes 1 day. Trace: push idx0. At idx1, 74>73 -> pop idx0, answer[0]=1-0=1. Push idx1. Continue for the rest.
Q26
In the same 'Daily Temperatures' trace [73, 74, 75, 71, 69], what is answer[4] (the last index)?
Index 4 (69) is the last day; there is no future day to compare against, so it has no warmer day ahead. Its answer stays at the default value 0.
Q27
What is the output of this code using std::stack with a custom struct?
#include <iostream>
#include <stack>
int main() {
    std::stack<int> s;
    for (int i = 1; i <= 3; ++i) s.push(i * i);
    int sum = 0;
    while (!s.empty()) {
        sum += s.top();
        s.pop();
    }
    std::cout << sum;
}
Pushed values: 1, 4, 9 (1*1, 2*2, 3*3). Popping and summing all of them regardless of order gives 1+4+9=14.
Q28
A function uses recursion to reverse a string via an implicit call stack: rev(s, i) prints s[i] AFTER the recursive call rev(s, i+1) returns. For input "abc" starting at i=0, in what order are characters printed?
This is the classic 'print after recursive call' pattern — it mimics how a stack unwinds. Calls go rev(0)->rev(1)->rev(2)->rev(3) (base case), then printing happens on the way back out: s[2]='c', s[1]='b', s[0]='a'. Output: 'c b a'.
Q29
Which scenario correctly triggers a Stack Underflow?
Stack Underflow specifically refers to attempting to remove or access data (pop/top) when the stack contains no elements to remove.
Q30
Trace the largest-rectangle-in-histogram monotonic stack algorithm on heights [2, 1, 2] (with an appended sentinel 0). At what point is the bar of height 2 at index 0 popped, and what area does it produce?
Push idx0 (h=2). At i=1, h=1 < 2, so we pop idx0. Its left boundary is empty stack (-1), right boundary is i=1, so width = 1 - (-1) - 1 = 1. Area = 2 * 1 = 2.
