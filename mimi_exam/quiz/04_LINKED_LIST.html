04. Linked List

Q1
On a 64-bit operating system, how much memory is consumed by a pointer variable?
On 64-bit architectures, memory addresses are 64-bit values, so every pointer variable consumes exactly 8 bytes of storage, regardless of what it points to.
Q2
How many link pointers are stored in each node of a Doubly Linked List?
Each node in a doubly linked list stores two pointers: next and prev.
Q3
What is a Circular Linked List?
A circular linked list forms a closed ring, so the last (tail) node points directly back to the first (head) node.
Q4
In a circular linked list, what does the tail node's next pointer refer to?
A circular list forms a closed ring, so the last (tail) node points directly back to the first (head) node.
Q5
For a Circular Singly Linked List where tail->next points back to head, which condition correctly detects that the list is empty?
Regardless of the circular wiring among existing nodes, an empty list still has no nodes at all, so head (and tail) remain nullptr, just like a standard empty linked list. The circular link only exists once nodes are present.
Q6
What is the worst-case time complexity of inserting an element at position k (where 0 < k < N) in a singly linked list of size N?
In a singly linked list, reaching position k requires traversing the list from the head. This traversal takes linear O(N) time.
Q7
What is the time complexity to delete the tail node of a Singly Linked List of size N, if we only maintain a head and tail pointer?
Even with a tail pointer, deleting the tail requires updating the second-to-last node's next pointer to nullptr. Since a singly linked list has no way to go backward from the tail, we must traverse from the head to find that second-to-last node, taking O(N) time.
Q8
What is the time complexity to find the length of a singly linked list if no length variable is cached?
Without a cached counter, we must traverse the list from head to tail, visiting all N nodes, giving O(N) time.
Q9
Given a singly linked list of size N with no tail pointer, what is the time complexity of push_back (inserting a new node at the end)?
Without a tail pointer, the only way to find the last node is to traverse the entire list starting from head, giving O(N). This is why a queue built on a linked list explicitly keeps a tail pointer, to achieve O(1) enqueue.
Q10
What is the main benefit of a Doubly Linked List over a Singly Linked List?
Because doubly linked list nodes store pointers to both next and prev, we can detach a node in place in O(1) without traversing to find its predecessor — something a singly linked list cannot do without extra work.
Q11
When inserting a new node at the front of a singly linked list (push_front), what pointer assignment must happen first to avoid losing access to the rest of the list?
You must first point the new node's next to the current head — new_node->next = head; — before updating the head pointer. Doing it in the other order would lose the reference to the rest of the list.
Q12
What is the output of the following linked list wiring logic?
struct Node { int val; Node* next; };
Node* head = new Node{1, nullptr};
Node* temp = new Node{2, nullptr};
temp->next = head;
head = temp;
std::cout << head->val << " " << head->next->val;
temp is initialized with val 2, and its next is set to head (which holds 1). Then head is reassigned to temp. So head->val is 2, and head->next->val is 1.
Q13
Where does pointer curr end up after this loop, on the list 1 -> 2 -> 3 -> 4 -> nullptr?
Node* curr = head;
while (curr != nullptr && curr->next != nullptr) {
    curr = curr->next->next;
}
curr starts at node 1. First iteration: curr = curr->next->next moves it to node 3. Second iteration: curr->next is node 4, and node 4's next is nullptr, so curr becomes nullptr. The loop then terminates.
Q14
We want to insert a new node with value 99 between the nodes holding 10 and 20 in the list 10 -> 20 -> 30. With pointer prev at the node holding 10, which statement order correctly performs the insertion?
You must save the old next pointer (the node holding 20) into newNode->next before overwriting prev->next. Reversing the order (option B) would make newNode->next point to newNode itself, breaking the list.
Q15
Trace this singly linked list deletion. Given 5 -> 8 -> 12 -> nullptr with prev at the node holding 5, what is the list after executing Node* target = prev->next; prev->next = target->next; delete target;?
target points to the node holding 8. prev->next is rewired to skip over it, pointing directly to the node holding 12 (target->next), before target is deleted. Result: 5 -> 12 -> nullptr.
Q16
What is the output of this pointer-swapping reversal trace on the list 1 -> 2 -> 3 -> nullptr?
Node* prev = nullptr;
Node* curr = head; // points to 1
while (curr != nullptr) {
    Node* next = curr->next;
    curr->next = prev;
    prev = curr;
    curr = next;
}
head = prev;
This is the standard iterative in-place reversal. Each node's next pointer is redirected backward toward prev before advancing. After the loop, prev holds the new head, and the list is fully reversed: 3 -> 2 -> 1 -> nullptr.
Q17
What does this code print, tracing the pointer reassignment carefully?
struct Node { int val; Node* next; };
Node a{1, nullptr}, b{2, nullptr}, c{3, nullptr};
a.next = &b;
b.next = &c;
Node* p = &a;
p = p->next;
p->val = 99;
std::cout << a.next->val;
p starts at &a, then p = p->next moves it to &b. p->val = 99 modifies node b's value directly, since p now points to the same memory as b. a.next still points to &b, so a.next->val prints 99.
Q18
A singly linked list node holding 5 is given directly via a pointer node (not the head, and we have no access to its predecessor). To delete it in O(1), we use the trick of copying the next node's value into node, then deleting the next node instead. For the list 3 -> 5 -> 8 -> nullptr, with node pointing to the node holding 5, what does the list look like after this trick?
Since we cannot reach the predecessor (the node holding 3), we fake deleting node itself: we copy the next node's value (8) into node, so node's value becomes 8, then delete the actual next node and relink node->next to skip past it. The list becomes 3 -> 8 -> nullptr, functionally the same as if the node holding 5 had been removed.
Q19
In the Doubly Linked List insertion diagram (inserting node N after node P, before node S), what is the correct 4-step pointer sequence?
The safe order sets N's own pointers first (N->next = P->next, which is S; N->prev = P), then fixes the old neighbor's back-pointer (P->next->prev = N, which must happen while P->next still refers to S, i.e. before overwriting P->next), and only then rewires P->next = N. Doing 'P->next = N' too early would lose the reference needed to update S->prev.
Q20
Which algorithm is used to detect cycles in a linked list using two pointers moving at different speeds?
Floyd's Cycle-Finding Algorithm uses a slow pointer moving 1 step at a time and a fast pointer moving 2 steps at a time.
Q21
Using Floyd's Cycle Detection (slow moves 1 step, fast moves 2 steps) on the list 1 -> 2 -> 3 -> 4 -> 2 (node 4 points back to node 2, forming a cycle), do slow and fast ever meet?
Because a cycle exists, fast can never reach nullptr — it keeps looping. Since fast gains on slow by 1 step every iteration within a finite cycle, they are mathematically guaranteed to eventually land on the same node.
Q22
To find the middle element of a linked list in a single pass, we should use:
Using the two-pointer technique: when the fast pointer reaches the tail, the slow pointer lands exactly on the middle node.
Q23
Trace this slow/fast pointer code to find the middle node of 1 -> 2 -> 3 -> 4 -> 5 -> nullptr:
Node* slow = head;
Node* fast = head;
while (fast != nullptr && fast->next != nullptr) {
    slow = slow->next;
    fast = fast->next->next;
}
// slow now points to the middle
fast moves 2 steps for every 1 step slow moves. Starting both at node 1: after iteration 1, slow=2, fast=3; iteration 2: slow=3, fast=5. At the next check, fast->next is nullptr, so the loop stops with fast at 5. slow lands on node 3, the middle of 5 elements.
Q24
What is the auxiliary space complexity of reversing a singly linked list of size N iteratively?
Reversing iteratively only requires updating pointers in place using a few temporary variables, giving constant O(1) space.
Q25
What is the auxiliary space complexity of the recursive (not iterative) version of linked list reversal, for a list of size N?
Each recursive call adds a new stack frame that isn't resolved until the base case is reached and calls start returning, so the call stack grows to depth N in the worst case — O(N) auxiliary space, unlike the O(1) iterative version.
Q26
What is the key advantage of using a Sentinel (Dummy) Node in a linked list?
With a dummy node, head is never nullptr, which removes the need for special code branches to handle empty lists or changes to the head.
Q27
A sentinel (dummy) head node is used so that dummy->next is the real head. What is the main benefit when deleting the actual first node of the list?
Without a sentinel, deleting the head requires special-case code, since the head pointer itself has no 'previous' node. With a dummy node placed before the real head, every deletion, including the first real node, follows the same 'unlink the node after prev' pattern, removing the edge case.
Q28
What happens when a 'dereferencing nullptr' error occurs in a linked list operation?
A null pointer does not refer to a valid memory address. Accessing ptr->next or ptr->val when ptr is nullptr triggers a runtime segmentation fault.
Q29
Trace merging two sorted lists 1 -> 3 -> 5 and 2 -> 4 using a dummy node and a tail pointer. What are the first three values appended to the merged result?
Compare the fronts: 1 vs 2, append 1, advance list1 to 3. Compare 3 vs 2, append 2, advance list2 to 4. Compare 3 vs 4, append 3, advance list1 to 5. The first three appended values are 1, 2, 3.
Q30
In the 'Remove Nth Node From End' technique, using two pointers separated by a gap of N+1 (with a dummy node), for the list 1 -> 2 -> 3 -> 4 -> 5 and N=2 (remove the 2nd node from the end), which node is removed?
The 2nd node from the end of [1,2,3,4,5] is 4 (the end is 5, one before it is 4). The two-pointer technique advances a fast pointer N+1 steps ahead first, then moves both pointers together until fast reaches nullptr — at that point, slow lands exactly before the target node, allowing its removal in one pass.
