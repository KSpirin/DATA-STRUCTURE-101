08. Binary Search Tree (BST)

Q1
An In-order traversal of a valid Binary Search Tree (BST) visits nodes in which sorted order?
By BST properties, left child < parent < right child. Traversing Inorder visits elements in ascending order.
Q2
When deleting a BST node with two children, what is a standard replacement strategy?
To delete a node with two children, replace it with its Inorder Successor or Inorder Predecessor.
Q3
What is the worst-case time complexity of searching for a key in a BST of size N?
If keys are inserted in sorted order, the BST becomes a single-linked list. Searching this tree takes linear $\mathcal{O}(N)$ time.
Q4
What is the maximum number of children a node can have in a Binary Search Tree?
Every node in a BST is restricted to a maximum of 2 child branches (left and right).
Q5
Which traversal can validate the BST property by verifying that each visited node is greater than the previously visited node?
Since inorder visits BST elements in sorted order, checking that current > previous validates the BST.
Q6
What is the Inorder Predecessor of the root node in a Binary Search Tree?
The inorder predecessor is the node visited immediately before the root, which corresponds to the maximum value in the root's left subtree.
Q7
What is the time complexity to find the minimum value in a balanced BST containing N nodes?
In a balanced BST, the height is $O(\log N)$, so searching for the leftmost node takes $\mathcal{O}(\log N)$ time.
Q8
Reconstructing a unique Binary Search Tree from a traversal sequence is possible with only a:
In a BST, the inorder sequence is simply the sorted keys. Thus, having either Preorder or Postorder traversal alone is sufficient.
Q9
If keys [10, 20, 30, 40] are inserted sequentially into an empty BST, what is the resulting height of the tree?
Inserting sorted keys generates a right-skewed tree structure with height 4.
Q10
If we insert keys [15, 10, 20, 8, 12] into an empty BST, which node is the parent of node 12?
12 goes right of 10. Thus, 10 is the parent of 12.
Q11
What is the average time complexity of inserting an element in a Binary Search Tree?
On average, a BST is balanced with height $O(\log N)$. Inserting an element traverses one path from root to leaf, taking $O(\log N)$ time.
Q12
Which of the following keys is NOT present in the left subtree of node 50 in a valid BST?
By the BST property, all keys in the left subtree of a node must be strictly less than that node's value. `51` is greater than 50, so it must be in the right subtree.
Q13
What is the height of a BST after inserting keys in the order: [10, 5, 15, 3, 7, 12, 18]?
Inserting these elements produces a perfect binary tree of height 3: Root 10; Left 5 (with children 3, 7); Right 15 (with children 12, 18).
Q14
What is the time complexity to search for a key in a skewed BST of size N?
A skewed BST is structurally identical to a linked list, requiring a linear scan of up to $N$ nodes, taking $O(N)$ time.
Q15
In a BST, the largest key is found by starting at the root and continuously traversing which pointer?
Since right child is always greater, the maximum element is found by traversing down the rightmost path of the tree.
Q16
For a BST initially containing keys [10, 5, 20] (with root 10). If we insert key 15, which node does it become the child of?
BST insertion follows recursive comparisons: 15 > 10, go to right child (20). 15 < 20, go to left child. Since left child of 20 is empty, 15 is inserted as the left child of 20.
Q17
Consider BST: Root 15, left child 10, right child 20, and left child of right child is 18. What is the Inorder Successor of 15?
The Inorder Successor of a node with a right child is the absolute minimum node in its right subtree. The right subtree contains {20, 18}. The minimum value is 18. Successor: 18.
