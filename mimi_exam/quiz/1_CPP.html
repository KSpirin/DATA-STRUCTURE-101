01. C++ Basics & Memory Management

Q1
Why must the preprocessor guard directive #ifndef SINGLE_LIST_H be placed at the top of header files?
In C++, including the same header multiple times causes duplicate class/variable definitions. Guards like #ifndef, #define, and #endif prevent compiling the definition block twice.
Q2
If class ClassA declares class ClassB to be a friend (i.e. friend class ClassB; inside ClassA), which of the following is true?
Friendship is one-way: ClassA declaring ClassB as a friend allows ClassB to access ClassA's private members, but not vice-versa. Friendship is also neither inherited nor transitive.
Q3
Consider the code: int x = 10; int& ref = x; ref += 5; x *= 2;. What is the value of ref after these operations?
A reference is an alias. Adding 5 to ref changes x to 15. Then multiplying x by 2 changes it to 30. Since ref aliases x, it evaluates to 30.
Q4
Which C++ operator is used to deallocate memory previously allocated with the new operator for a single object?
For single objects allocated with new, use delete. For array allocations like new Type[N], use delete[].
Q5
Which member function signature correctly defines a read-only 'accessor' that prevents modifying the calling object's member variables?
Placing the keyword const after the parameter list (e.g. double abs() const;) tells the compiler that the function is a read-only accessor and cannot modify member variables.
Q6
What is the primary difference between a C++ struct and a C++ class?
In C++, the only semantic difference is that a struct defaults to public member visibility and inheritance, while a class defaults to private member visibility and inheritance.
Q7
Which of the following describes the C++ 'Rule of 5' for resource management?
The Rule of 5 states that if you need to custom-implement any of the following, you likely need all 5: Destructor, Copy Constructor, Copy Assignment Operator, Move Constructor, and Move Assignment Operator.
Q8
Why is it critical to declare a base class destructor as virtual in an inheritance hierarchy?
If a derived object is deleted via a base class pointer and the base class destructor is not virtual, the derived class destructor will not execute, leading to memory leaks.
Q9
What occurs when an exception is thrown in C++ but no matching try-catch block catches it?
Uncaught exceptions result in the C++ runtime environment calling std::terminate() (which defaults to abort()), ending program execution immediately.
Q10
What is the consequence of executing: int* p = new int(5); delete p; std::cout << *p;?
Deleting a pointer deallocates the memory it points to. Accessing it afterward (dangling pointer reference) results in Undefined Behavior, which could crash the program or output garbage values.
Q11
What is the return type of the move assignment operator in C++?
Like the copy assignment operator, the move assignment operator returns a reference to the calling object (ClassType&) to support chain assignments.
Q12
Which keyword is used to specify that a function can be evaluated at compile-time in C++?
The keyword constexpr specifies that the value of a function or variable can be computed at compile-time.
Q13
What occurs during a shallow copy of a class containing a raw pointer to dynamically allocated memory?
Shallow copying copies only pointer addresses, not the underlying heap memory. This leads to two instances managing the same memory, triggering double frees on destruction.
Q14
Which of the following describes the difference between delete and delete[]?
For arrays allocated via new Type[N], delete[] ensures the compiler calls the destructor for all $N$ objects in the array. delete only calls it for the first.
Q15
What does the C++ noexcept specifier indicate on a function declaration?
The noexcept specifier tells the compiler and runtime that a function is guaranteed not to throw any exceptions, allowing performance optimizations during move operations.
Q16
What is the output of the following C++ code?
#include <iostream>
void modify(int* a, int& b) {
    *a += 5;
    b *= 2;
}
int main() {
    int x = 10, y = 20;
    modify(&x, y);
    std::cout << (x + y);
    return 0;
}
Inside modify, x is modified via pointer dereference (*a += 5) to 15. y is passed by reference, so b *= 2 modifies y to 40. The sum 15 + 40 equals 55.
Q17
Read the following class definitions. What is printed when this program is executed?
#include <iostream>
class Test {
public:
    Test() { std::cout << "C"; }
    Test(const Test&) { std::cout << "K"; }
    Test& operator=(const Test&) { std::cout << "A"; return *this; }
};
int main() {
    Test t1;
    Test t2 = t1;
    Test t3;
    t3 = t2;
    return 0;
}
1) Test t1; calls default constructor, printing 'C'. 2) Test t2 = t1; is copy initialization, invoking the copy constructor, printing 'K'. 3) Test t3; calls default constructor, printing 'C'. 4) t3 = t2; is assignment on an already-constructed object, invoking the assignment operator, printing 'A'. Output: CKCA.
Q18
Predict the output or behavior of this code block representing inheritance destruction:
#include <iostream>
class Base {
public:
    ~Base() { std::cout << "B"; }
};
class Derived : public Base {
public:
    ~Derived() { std::cout << "D"; }
};
int main() {
    Base* ptr = new Derived();
    delete ptr;
    return 0;
}
Because the Base class destructor is not declared virtual, deleting a Derived object via a Base pointer leads to static dispatch: only the Base destructor is called, printing 'B'. Derived destructor is bypassed, leaking memory.
Q19
Trace the recursion. What value does func(4) return?
int func(int x) {
    if (x < 1) return 0;
    return x + func(x - 1);
}
func(4)=4+func(3), func(3)=3+func(2), func(2)=2+func(1), func(1)=1+func(0), func(0)=0. Summing back: 1, 3, 6, 10. func(4)=10.
Q20
Trace this loop. What is arr[3] after execution?
int arr[5];
arr[0] = 1;
for (int i = 1; i < 5; ++i) {
    arr[i] = 2 * arr[i - 1] + 1;
}
arr[0]=1, arr[1]=2*1+1=3, arr[2]=2*3+1=7, arr[3]=2*7+1=15.
Q21
What is printed by this operator chaining?
#include <iostream>
int sqr(int x){ return x*x; }
int main(){
    std::cout << "val=" << sqr(3) << std::endl;
}
cout << is evaluated left to right: ((cout << "val=") << sqr(3)) << endl. sqr(3) evaluates to 9, so it prints 'val=9'.
Q22
Given the preprocessor performs pure text substitution (no syntax checking), what is printed?
#include <iostream>
#define SQUARE(x) x * x
int main() {
    std::cout << SQUARE(2 + 3);
}
Textual substitution gives 2 + 3 * 2 + 3, which by operator precedence evaluates as 2 + (3*2) + 3 = 2+6+3 = 11, not 25. This is why function-like macros are dangerous without parentheses.
Q23
Trace the following namespace resolution. What is printed?
#include <iostream>
namespace lab {
    int n = 4;
}
int n = 10;
int main() {
    std::cout << n << " " << lab::n;
}
The unqualified n inside main() refers to the global n (10). lab::n explicitly accesses the namespace-scoped n (4). Output: '10 4'.
Q24
A student forgets a header guard and includes 'Node.h' from two different .cpp translation units that are linked into the same executable. What is the most likely resulting error?
Without a header guard, if the header defines (not just declares) functions/variables and is included in multiple .cpp files, each translation unit emits its own copy of the symbol, and the linker reports 'multiple definition' when combining object files.
Q25
Trace pointer arithmetic. What does this print?
#include <iostream>
int main() {
    int arr[4] = {10, 20, 30, 40};
    int* p = arr;
    p += 2;
    std::cout << *p << " " << *(p - 1);
}
p starts at arr[0]. p += 2 advances it by 2 elements (not bytes) to arr[2] = 30. *(p-1) is arr[1] = 20. Output: '30 20'.
Q26
What is printed when a template function is instantiated with two different types?
#include <iostream>
template <typename T>
T sqr(T x) { return x * x; }
int main() {
    std::cout << sqr(3) << " " << sqr(2.5);
}
The compiler instantiates sqr and sqr separately at compile time based on the argument types. sqr(3) -> 9, sqr(2.5) -> 6.25.
Q27
Given a class with a virtual destructor in the base and a derived class allocated via a base pointer, what happens on delete?
class Base { public: virtual ~Base(){ /*A*/ } };
class Derived : public Base { public: ~Derived(){ /*B*/ } };
Base* b = new Derived();
delete b;
Because ~Base() is virtual, delete b performs a virtual dispatch: Derived's destructor runs first (cleaning up derived members), then it implicitly calls Base's destructor. Full and correct cleanup occurs.
Q28
If the base class destructor above were NOT declared virtual, what would happen instead on delete b;?
Without a virtual destructor, deleting a derived object through a base pointer only calls the base class's destructor (static binding). Any resources owned exclusively by Derived are leaked — this is why polymorphic base classes should always have virtual destructors.
Q29
What does sizeof most likely report for this struct on a typical 64-bit system (assume default alignment)?
struct Mixed {
    char c;   // 1 byte
    int i;    // 4 bytes
    char* p;  // 8 bytes
};
c takes offset 0 (1B) then 3B padding so int i aligns to offset 4 (4B, ends at 8). char* p needs 8-byte alignment, already satisfied at offset 8 (8B, ends at 16). Struct alignment (8, from the pointer) already divides 16 evenly, so no trailing padding is needed. Total: 16 bytes.
Q30
Trace this static local variable across multiple calls. What is printed?
#include <iostream>
void counter() {
    static int count = 0;
    count++;
    std::cout << count << " ";
}
int main() {
    counter();
    counter();
    counter();
}
A static local variable is initialized only once and retains its value between function calls (unlike a normal local variable, which is re-created and re-initialized every call). Each call increments the same persistent count: 1, then 2, then 3.
